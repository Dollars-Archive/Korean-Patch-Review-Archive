# 웹GPT 평가 요청 양식

아래 요청에서 게임명·기종을 바꿔 웹GPT에 전달하세요. 출력된 JSON을 `docs/data/games.json`의 `games` 배열에 추가하면 사이트가 평점순으로 자동 정렬합니다.

---

**[게임명] / [기종]을 한글패치로 플레이할지 판단할 수 있게 평가해줘.**

- 게임 자체의 완성도를 **10점 만점**으로 평가하고 점수 이유, 구체적인 장점·단점, 잘 맞는 취향을 스포일러 없이 정리해줘.
- 해당 기종의 리뷰와 실제 자료를 조사하고, 확인한 출처 URL을 넣어줘. 다른 기종의 평가를 그대로 옮기지 마.
- 직접 플레이했다고 꾸미거나, 유저 평균 점수·출처·패치 버전을 만들지 마. 자료 기반 편집 평가임을 밝혀줘.
- 점수는 숫자(예: `8.5`)로 적고, 근거가 부족하면 억지로 점수를 매기지 말고 `null`과 사유를 적어줘.
- 한글패치 대상 기종·판본·배포 페이지를 확인하고, 패치에 관한 주의점은 `patch.notes`에 따로 적어줘.
- 패치 페이지가 확인되면 `available`, 미확인이면 `unconfirmed`, 배포가 중단됐다면 `stopped`로 적어줘. `available`일 때만 실제 패치 배포 페이지 URL을 넣어줘.
- 확인하지 못한 선택 정보는 빈 문자열·빈 배열로 남겨줘. 게임 원본 파일 링크는 넣지 마.

**결과는 아래 구조의 JSON 객체 하나로 출력해줘.** 예시 내용은 실제 조사 결과로 바꾸고, 이미 등록된 게임의 ID는 유지해줘.

```json
{
  "id": "game-title-psp",
  "title": "게임 제목",
  "original": "원제",
  "platforms": ["psp"],
  "genres": ["ADV"],
  "score": null,
  "cover": {"url": "", "source": "", "platform": "psp", "type": "Box - Front", "region": "Japan"},
  "summary": "게임 소개와 점수 이유, 추천 취향. 자료 기반 평가임을 명시.",
  "pros": ["구체적인 장점"],
  "cons": ["구체적인 단점"],
  "sources": [{"label": "자료 이름", "url": "https://example.com/verified-source"}],
  "patch": {"status": "unconfirmed", "url": "", "notes": "패치 판본·확인 날짜·주의사항"},
  "reviewedAt": "YYYY-MM-DD",
  "reviewer": "WebGPT"
}
```

- `id`: 소문자 영문·숫자·하이픈, 최대 100자. 한 번 등록한 ID는 변경하지 않습니다.
- `score`: `0`~`10` 숫자 또는 미평가 `null`. 문자열 `"8.5"`는 사용하지 않습니다.
- `platforms`: `ps1`, `ps2`, `psp`, `psvita`, `ps3`, `ps4`, `ps5`, `dreamcast`, `ds`, `3ds`, `switch`, `pc`, `saturn`, `snes`, `gba`, `other` 중 선택합니다.
- `genres`: `ADV`, `RPG`, `ACT`, `SLG`, `SIM`, `PUZ` 등 장르 이름을 배열로 적습니다.
- `reviewedAt`: 실제 조사 날짜, 모르면 빈 문자열. 예시 날짜·URL은 그대로 제출하지 않습니다.

## 박스 이미지 등록

- 새 게임을 등록할 때 평가 대상과 **같은 기종·판본의 실제 패키지 앞표지**를 찾아 `cover`에 함께 등록한다. 제목이 비슷한 다른 작품·후속작·다른 기종 표지, 뒷표지, 스크린샷, 홍보 배너, AI 생성 이미지는 사용하지 않는다.
- LaunchBox의 해당 기종 일본 앞표지를 우선 확인하고 없으면 공식 제작사·판매점 자료에서 확인한다. 다운로드 전용으로 실물 패키지가 없는 작품은 해당 기종 공식 스토어 타이틀 아트를 사용하고 `type`을 `Official store artwork`로 표시한다.
- `cover`는 `{ "url": "직접 이미지 URL 또는 covers/파일명.webp", "source": "이미지가 확인된 출처 페이지 URL", "platform": "ps2", "type": "Box - Front", "region": "Japan" }` 형식이다. `platform`은 실제 평가 기종과 일치해야 한다. 이미지 검색 결과 페이지나 HTML 문서를 `url`에 넣지 않는다.
- 자산 파일 저장 도구가 있으면 가로 최대 320px의 WebP를 `docs/covers/<게임id>-<내용해시>.webp`로 저장하고 `cover.url`에는 `covers/<파일명>.webp`를 쓴다. 자산 저장이 불가능해도 실제 확인한 공개 직접 이미지 URL과 출처를 기록할 수 있다. 비율을 유지하고 표지 일부를 잘라내지 않는다.
- 화면 왼쪽은 **박스 이미지 → 그 아래 평점 박스** 순서다. 평가·점수·장단점·찜·삭제 기록은 표지 변경 때문에 바꾸지 않는다.
- 표지를 끝내 확보하지 못하면 가짜 이미지를 넣지 말고 `cover.url`을 비워 “표지 확보 대기”로 보고한다. 기존에 확인한 올바른 표지가 있으면 보존한다.

## 사용자 제공 한글패치 주소: 접속하지 않고 등록

- 사용자가 레트로DB(`https://redb.me/kr/6493` 같은 주소) 또는 다른 한글패치 주소를 주면 **해당 주소를 열지 말고 해당 게임의 `patch.url`에 그대로 등록**한다. 이것은 주소 형식 예시이며 게임과의 대응 관계를 뜻하지 않는다.
- GET·HEAD 요청, 링크 미리보기·썸네일 생성, 링크 유효성 검사, 리다이렉트 추적, 외부 도구·프록시를 통한 우회 접속을 모두 하지 않는다. 평가 자료를 별도로 조사하더라도 사용자 제공 패치 주소는 접속하지 않는다.
- `patch.status`는 사용자에게 별도 확인된 배포 상태가 없으면 `unconfirmed`로 둔다. 그래도 `patch.url`은 비우지 않는다. `patch.notes`에는 “사용자 제공 한글패치 주소 · AI 미접속 · 배포 상태/버전 미검증”을 기록한다. 접속·배포를 확인했다고 쓰지 않는다.
- 화면은 `patch.url`에 안전한 HTTP(S) 주소가 있으면 **평점 박스 바로 아래에 ‘한글패치’ 링크**를 표시한다. `unconfirmed`라도 제공된 주소를 표시하며, 사용자가 클릭할 때만 이동한다. 프로그램에서 미리 읽거나 다운로드하지 않는다.
- 해당 게임을 수정할 때 기존 게임 정보·표지·평점·장단점·ID·다른 항목은 보존한다. 게임명·기종이 이미 주어졌으면 다시 묻지 않는다. URL만으로 대상 게임을 알 수 없으면 주소를 열거나 게임을 추측하지 말고 게임명·기종만 사용자에게 묻는다.
- 이 사용자 제공 링크 예외는 “미확인 링크는 비운다/확인한 URL만 등록한다”는 일반 규칙보다 우선한다. 게임 원본 파일을 찾아 추가하거나 링크 내용을 읽으라는 뜻이 아니다.

등록 형태(형식 예시):
```json
"patch": {
  "status": "unconfirmed",
  "url": "https://redb.me/kr/6493",
  "notes": "사용자 제공 한글패치 주소 · AI 미접속 · 배포 상태/버전 미검증"
}
```
